# 一键宏配置工具（play-macro）

基于 `@nut-tree/nut-js`（键鼠模拟）+ `uiohook-napi`（全局监听）的可配置化一键宏 GUI 工具。
原参考脚本 `D:\keep\node-w-macro` 的四个问题均已解决：

1. **注释与代码不一致** → 所有参数在界面中配置并即时保存，不存在文字与代码脱节
2. **参数硬编码** → 全部参数（触发键、操作序列、延迟、倍率、抖动、保持时长）动态读取自 JSON 配置
3. **延迟单位/抖动不直观** → 界面直接填写毫秒、倍率（0.5x~2x）、±ms 抖动
4. **出错时按键卡住** → 宏执行引擎用 `try/finally` + 按住键集合兜底释放，无论成功/失败/异常退出都确保所有按下的键被松开

## 一、方案说明

### GUI 技术选型：本地 Web 服务（Express + 浏览器页面）

选型理由：

| 维度 | 说明 |
| --- | --- |
| 跨平台 | 浏览器即界面容器，Windows / macOS / Linux 一致 |
| 轻量 | 仅 Express（HTTP 静态与 REST）+ ws（WebSocket 实时推送），无重型 GUI 框架 |
| 交互 | HTML/CSS/JS 轻松实现拖拽排序、按键捕获、录制等复杂交互 |
| 集成 | 与 Node.js 主进程同进程，直接调用 nut-js 与 uiohook-napi |
| 安全 | 仅绑定 `127.0.0.1`，不对外网开放 |

### 整体架构（文字描述）

```
┌────────────────────────────── 浏览器（GUI 配置界面）──────────────────────────────┐
│  触发/退出键 · 触发模式 · 操作序列（增删改/拖拽/录制）· 时序参数 · 运行控制 · 日志    │
└───────────────▲───────────────────────────────▲─────────────────────────────────┘
                │ HTTP（REST API）               │ WebSocket（状态/当前步骤/日志/录制事件）
┌───────────────┴───────────────────────────────┴─────────────────────────────────┐
│                        src/server.js —— Express 服务入口                          │
│            静态页面 + REST API + WebSocket 推送 + 模块组装                          │
└───────────▲──────────────────────────┬───────────────────────────┬───────────────┘
            │                           │                           │
   ┌────────┴────────┐         ┌────────┴────────┐         ┌────────┴────────┐
   │ src/config.js   │         │ src/engine.js   │         │ src/listener.js │
   │ 配置管理/持久化   │         │ 宏执行引擎        │         │ uiohook 全局监听  │
   │ 多方案/校验/冲突  │         │ nut-js 键鼠模拟   │         │ 触发/退出/录制事件 │
   └────────┬────────┘         │ busy 防重入       │         └────────┬────────┘
            │                  │ try/finally 释放  │                  │ 触发/退出
            │                  └────────┬────────┘                  │
            │                           │ 动态读取                    │
            └───────────────► 配置对象（config/*.json）◄─────────────┘
                        src/keymap.js：键名 ↔ nut-js Key ↔ uiohook keycode
```

### 关键逻辑设计

- **防重入**：引擎 `busy` 标志，宏执行中新的触发直接忽略并记日志
- **防重复触发**：监听器 `triggerDown` 标志，触发键按住期间不重复触发
- **多宏同时运行**：每个方案就是一个宏（触发键 + 操作序列 + 退出键）。方案列表可同时运行多个方案，
  全局监听按触发键分发到对应方案；运行新方案前做热键冲突检测（触发/退出键与其他已运行方案重复时拒绝），
  退出键只停止本方案的监听；按住循环按方案独立停止（`engine.stop(schemeName)`）
- **防卡键（核心修复）**：引擎维护 `heldKeys` / `heldButtons` 集合记录所有按下的键；
  每次执行用 `try/finally` 包裹，`finally` 中遍历释放全部按键，单个失败不影响其余
- **所有延迟从配置读取**：固定/随机延迟、步骤间隔（固定或随机区间）、全局倍率、±ms 抖动、
  按键保持时长（固定/随机/保持到显式松开），全部动态计算，零硬编码
- **测试运行**：不经过全局监听，直接对当前配置执行一遍（便于调参）
- **录制模式**：独立于"启动监听"运行（引用计数管理 uiohook 生命周期），
  录制事件经 WebSocket 实时转发到前端组装为操作序列
- **热键冲突检测**：触发键/退出键与操作序列按键重复时，前后端双重校验拒绝

## 三、配置文件示例（config/default.json）

```json
{
  "version": 1,
  "schemeName": "示例方案（W+右键）",
  "trigger": { "key": "C", "mode": "once", "holdLoopInterval": 300 },
  "exitKey": "X",
  "timing": {
    "globalSpeed": 1.0,
    "stepJitter": 0,
    "holdDuration": null,
    "disableNutAutoDelay": true
  },
  "steps": [
    { "type": "pressKey", "key": "W", "hold": true, "holdDuration": null, "interval": { "mode": "fixed", "value": 0 } },
    { "type": "randomDelay", "min": 106, "max": 194, "interval": { "mode": "fixed", "value": 0 } },
    { "type": "mouseClick", "button": "right", "interval": { "mode": "fixed", "value": 0 } },
    { "type": "randomDelay", "min": 103, "max": 197, "interval": { "mode": "fixed", "value": 0 } },
    { "type": "releaseKey", "key": "W", "interval": { "mode": "fixed", "value": 0 } }
  ]
}
```

### 步骤类型一览

| type | 字段 | 说明 |
| --- | --- | --- |
| `pressKey` | `key`、`hold`、`holdDuration` | 按下按键。`hold=true` 保持按住；`holdDuration` 可配固定/随机自动松开，为 `null` 时保持到显式 `releaseKey` 或宏结束兜底释放 |
| `releaseKey` | `key` | 松开按键 |
| `mouseClick` | `button`（left/right/middle） | 鼠标左/右/中键点击 |
| `mouseMove` | `mode`（absolute/relative）、`x`、`y` | 绝对坐标移动或相对位移 |
| `fixedDelay` | `ms` | 固定延迟 |
| `randomDelay` | `min`、`max` | 随机延迟区间 |

每个步骤均可选 `interval`：`{ "mode": "fixed", "value": N }` 或 `{ "mode": "random", "min": A, "max": B }`，表示本步骤执行完到下一步之间的间隔；另有全局 `timing.stepJitter`（±ms 抖动）与 `timing.globalSpeed`（0.5x~2x 倍率）作用于所有延迟。

## 四、使用说明

### 1. 安装依赖

```bash
cd D:\keep\play\play-macro
npm install
```

### 2. 启动

```bash
npm start
# 或双击 start.cmd（推荐：自动请求管理员权限）
```

**管理员权限说明**：宏需要全局键盘钩子（uiohook）与键鼠模拟，且要能作用于以管理员身份运行的目标程序（如部分游戏），**建议以管理员身份运行本工具**。
双击 `start.cmd` 会自动检测权限：非管理员时弹出 UAC 确认，点「是」即以管理员身份运行（普通终端里 `npm start` 不会自动提权，可右键终端「以管理员身份运行」后再执行）。

**端口说明**：默认监听 `127.0.0.1:8765`；若该端口已被其他实例占用，会自动顺延（8765 → 8766 → …）并在启动日志中提示实际访问地址。

启动后自动打开浏览器（设置环境变量 `MACRO_NO_BROWSER=1` 可禁用自动打开）。
控制台默认静默，如需打印运行日志，设置环境变量 `LOG=DEBUG` 后启动（界面日志面板不受影响）。

### 3. 配置

- **触发与退出**：点击输入框后按下目标键完成捕获（支持 A~Z、数字、F1~F12、小键盘、功能键等），
  也可通过下拉选择鼠标侧键 Mouse4/Mouse5 作为触发/退出源
- **触发模式**：单次触发（按一次执行一次）/ 按住循环（按住持续执行、松开即停）
- **操作序列**：「添加步骤」逐条配置，或点击「🎙 录制」手动操作一遍自动生成；
  卡片可拖拽排序、双击编辑、✕ 删除；每步可独立设置操作间隔
- **时序与流畅度**：全局延迟倍率、每步抖动 ±ms、按键保持时长（固定/随机/保持到显式松开）、
  nut.js 自动延迟开关（默认关闭，时序完全自控）
- **保存**：点击「保存配置」写入 `config/<方案名>.json`
- **方案管理**：界面左侧「方案列表」面板集中管理，**支持多方案同时运行**：
  - 点击方案卡片 → 切换到该方案（编辑焦点切换，不影响已运行方案的监听）
  - 点「▶ 运行」→ 将该方案加入监听集合（多个方案可同时运行，按各自触发键执行对应宏）
  - 点「⏹ 停止」→ 仅停止该方案的监听（运行中的方案卡片显示绿色运行徽标）
  - 点「⧉ 复制」→ 基于该方案复制一套新的（含全部步骤与参数）
  - 点「✕」删除（内置 default 不可删除；运行中的方案会先停止再删除）
  - 顶部方案栏另有：新建 / 删除当前 / 导入 / 导出 JSON

### 4. 运行

1. 点击「▶ 运行当前方案」，或直接在左侧方案列表点「▶ 运行」加入多个方案 —— 全局同时监听这些方案的触发键与退出键
2. 在任意程序中按下某个方案的触发键，执行对应宏；按住循环模式下松开触发键即停止该宏
3. 按某方案的退出键（默认 X），仅停止该方案的监听；「⏹ 停止全部」一次停止所有方案
4. **热键冲突**：若新运行方案的触发/退出键与已在运行方案重复，会被拒绝并提示冲突来源
5. 「🧪 测试运行」不经过全局监听，直接执行一遍当前配置用于调参
6. 关闭程序窗口或按 `Ctrl+C` 退出（退出前自动释放所有按键、停止全部监听）

## 五、注意事项

### 权限要求

- **Windows**：无特殊权限要求（键鼠模拟与全局钩子均可用）
- **macOS**：首次运行需在「系统设置 → 隐私与安全性 → 辅助功能」中授权终端/Node 进程；
  键鼠模拟依赖辅助功能权限
- **Linux**：部分发行版需要 `libXtst`/`libX11` 等依赖（nut-js libnut 原生绑定）

### 已知限制

1. **全局监听为系统级钩子**：启动监听后，在任意程序（含密码输入框）按下触发键都会触发宏，
   建议配置后先用「测试运行」验证，避免误触发
2. **触发键不要设为操作序列中的按键**（前后端均会做冲突检测并拒绝保存/启动）
3. **鼠标侧键触发**：仅支持 Mouse4/Mouse5；MouseLeft/Right 不建议作为触发键（会干扰正常点击）
4. **按住循环模式下**，触发键必须持续按住；期间程序其余操作不受影响，但宏会反复执行
5. **nut.js 自动延迟关闭后**，键鼠事件间隔完全由配置决定；若某些程序对事件间隔敏感，
   可在「时序」中重新开启自动延迟或调大步骤间隔
6. **录制模式**：键盘只录制按下/松开成对事件（`pressKey` + `releaseKey`），鼠标录制点击；
   触发键/退出键本身不会被录进序列
7. **服务仅监听 127.0.0.1**：如需局域网访问，修改 `src/server.js` 中 `HOST` 为 `0.0.0.0`
   （注意键鼠模拟工具暴露给局域网存在风险，不建议）
8. **多方案运行冲突**：同时运行多个方案时，各方案的触发键/退出键之间不得重复；
   运行新方案时后端做冲突检测，冲突则拒绝并提示与哪个方案重复（前端卡片同样以绿色徽标区分运行态）
